# Модерн Машинери Фар Ист — сайт филиала в Хабаровске

Бэкенд сайта хабаровского филиала: каталог спецтехники с нормализованными
характеристиками и фасетными фильтрами, каталог запасных частей, модуль
сервисных услуг, контент, приём и маршрутизация заявок с соблюдением 152-ФЗ и
SEO-слой под региональные запросы.

Объём соответствует разделу 7 документа `modern-machinery-plan-stage-0-1.md`
(этап 1, сужённый до Хабаровска). Дизайн-документ — в
`docs/superpowers/specs/`, принятые по ходу работы решения и спорные моменты —
в [`docs/DECISIONS.md`](docs/DECISIONS.md).

## Стек

| Слой | Решение |
|---|---|
| Backend | Python 3.13, Django 5.2 LTS, Django REST Framework |
| БД | PostgreSQL 17 (`pg_trgm`, `unaccent`, полнотекстовый поиск, JSONB) |
| Кэш и очереди | Redis, Celery (worker + beat) |
| Фронт | Django-шаблоны, HTMX, рукописный CSS без сборки |
| Инструменты | uv, ruff, pytest, pre-commit |
| Инфраструктура | Docker Compose, gunicorn, nginx |

## Быстрый старт

```bash
make env          # создаст .env из шаблона
make up           # поднимет приложение, PostgreSQL, Redis, worker и beat
make seed         # наполнит базу демонстрационными данными
make superuser    # создаст администратора
```

Сайт — <http://127.0.0.1:8000>, админка — `/admin/`, документация API —
`/api/docs/`.

### Без Docker

```bash
make install                       # зависимости и pre-commit
createdb modern_machinery          # нужен свой PostgreSQL
make migrate seed
make run
```

При отсутствии Redis укажите в `.env` значение `CACHE_URL=locmem://` — кэш
переедет в память процесса, приложение останется полностью работоспособным.

## Возможности

**Каталог техники.** Фасетные фильтры по бренду, типу и восьми числовым
характеристикам; счётчики пересчитываются под уже выбранные условия. Разделы
панели сворачиваются по отдельности. Поиск переживает опечатки и кириллическое
написание брендов: «экскаватр» и «Коматсу» находят то же, что «экскаватор» и
«Komatsu».

**Сравнение моделей.** До четырёх машин бок о бок, различающиеся параметры
выделены. Выбор хранится в браузере, а подобранный набор передаётся ссылкой.

**Посадочные подборки** под региональные запросы: `/katalog/ekskavatory-komatsu-habarovsk/`
вместо набора параметров в адресе. Со своим заголовком, текстом и микроразметкой.

**Запчасти.** Поиск по артикулу в любом написании, применимость к технике,
статусы наличия.

**Услуги сервисного центра** — самостоятельный раздел с ценами и сроками.

**Заявки** с маршрутизацией по отделам, многоуровневой защитой от спама и
соблюдением 152-ФЗ.

**Изображения** конвертируются в WebP, для плитки генерируется превью: страница
каталога весит 190 КБ вместо 1,2 МБ. Позициям без фотографии рисуется заглушка
в стиле макета.

**SEO:** карта сайта на 361 адрес, канонические адреса, микроразметка
`LocalBusiness` / `Product` / `BreadcrumbList`, карта проезда, редиректы и
журнал 404.

## Что стоит посмотреть в первую очередь

**Нормализация характеристик** — `apps/specs/normalization.py`. Разбирает
`«257 кВт»` в число и единицу, `«6,6–7,4 м»` — в диапазон, сводит
`«Мощность двиг., кВт»` и `«мощность двигателя»` к одному справочному
параметру. Именно это делает возможными фильтры «мощность от и до», которых нет
на текущем сайте.

**Фасетные фильтры** — `apps/catalog/services/filters.py` и `facets.py`.
Фильтрация идёт `EXISTS`-подзапросами, а не цепочкой JOIN: план запроса
предсказуем, строки не размножаются. Счётчики считаются по выборке, к которой
применены все условия кроме собственного, — иначе панель обещает результаты,
которых нет. Кэш инвалидируется версией каталога: 32 запроса на холодную,
9 с прогретым кэшем.

**Защита формы заявок** — `apps/leads/throttling.py`, `apps/leads/forms.py`,
`apps/leads/services/antispam.py`. Капчи нет намеренно. Вместо неё: две корзины
дросселирования по IP (длинная и короткая), скрытое поле-ловушка, минимальное
время заполнения формы с подписанной меткой времени и дедупликация повторных
отправок. Корзина общая для API и HTML-формы — перейти с одной точки входа на
другую и обойти лимит нельзя.

**Маршрутизация заявок** — `apps/leads/services/routing.py`. Правила
редактируются в админке: заявка на вилочный погрузчик уходит на `forklift@`,
запрос запчастей — в отдел запчастей. Если правило не нашлось, письмо идёт на
резервный адрес — заявка не теряется никогда.

**152-ФЗ** — версионирование согласия (`ConsentVersion`), поле `purge_after` и
ежедневная задача Celery, обезличивающая просроченные заявки. Сама заявка при
этом сохраняется: статистика обращений остаётся, персональные данные — нет.

## API

`/api/v1/`: `machines` (с фильтрами, фасетами и поиском), `brands`,
`categories`, `machine-types`, `parts`, `part-categories`, `services`,
`service-categories`, `branches`, `pages`, `news`, `vacancies`,
`leads` (только создание), `tco/calculate`.

Схема OpenAPI — `/api/schema/`, интерактивная документация — `/api/docs/`.
Чтение доступно анонимно; единственная ручка записи — создание заявки, и она
закрыта дросселированием.

Примеры:

```bash
curl "http://127.0.0.1:8000/api/v1/machines/?brand=komatsu&spec_engine_power_min=200&in_stock=1"
curl "http://127.0.0.1:8000/api/v1/parts/?q=600%20311%203750"
curl "http://127.0.0.1:8000/api/v1/machines/facets/"
```

## Тесты

525 тестов, покрытие 98%, порог в конфигурации — 90%. Прогон идёт на настоящем
PostgreSQL: проект опирается на полнотекстовый поиск, GIN-индексы, `pg_trgm`,
`ArrayField` и частичные уникальные индексы, которых на SQLite попросту нет.

```bash
make test          # с проверкой покрытия
make cover         # HTML-отчёт в htmlcov/
```

Отдельно зафиксировано число SQL-запросов на страницу: если `prefetch_related`
потеряется при следующей правке, тест поймает возвращение N+1.

## Что не входит в этап 1

Личный кабинет клиента и парк техники с серийными номерами, интеграция с 1С и
реальные остатки, онлайн-оплата, телематика KOMTRAX, англоязычная версия.
Схема спроектирована так, чтобы эти модули добавлялись новыми таблицами и
внешними ключами, без переписывания существующих моделей.
